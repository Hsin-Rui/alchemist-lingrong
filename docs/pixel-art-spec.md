# 採集小遊戲・像素美術規範（Epic 2）

> 對應：`docs/game-design.md` §12（玩法權威）。本檔是採集地下城的**美術與呈現規範**：畫風、調色盤、圖塊／角色／道具清單、檔案格式、動畫與轉場。
> 適用範圍：**只有採集小遊戲**。主遊戲（炎洗宮、送禮、結算…）維持原本的 Q 版插畫風，不要改。像素風本身就是「進入另一個模式」的訊號。

---

## 1. 風格目標

- **超任（SNES）時代的 16-bit 俯視 RPG 質感**，3/4 俯視視角（看得到牆面正面，像風來的希煉、聖劍傳說那種角度）。不做 HD-2D（沒有 3D 景深、移軸模糊、即時光影）。
- 原創美術：不描、不仿任何既有遊戲的圖塊或角色。
- 角色是 **Q 版 2 頭身像素小人**，跟主遊戲立繪的配色、服裝特徵一致（零溶穿淡藍宮裝、戴小旗頭，侍衛穿石青勁裝、戴紅纓暖帽），讓人一眼認得出是同一個角色。
- 調性跟主遊戲一樣明亮、可愛、帶點搞笑感，不陰森。白天的御花園。

### 品質底線（每張圖都要過）

1. 角色和道具一律有 **1px 深色外框**（用 `k`），地形圖塊不用外框。
2. 光源固定在**左上**：亮面在左上，陰影在右下。每種材質用 2～3 階色（亮／中／暗），**不做枕頭式陰影**（從外往內一圈一圈變暗）。
3. **1 倍大小也要看得懂**：零溶靠淡藍衣服加頭上白花辨認，侍衛靠石青衣服、紅帽纓加腰刀辨認，稀有素材靠紫色和閃光辨認。
4. 遞色（dithering）只用在大面積材質（草地、水面、樹籬），角色和道具不遞色。
5. 每張 sprite 含透明最多 16 色（比照 SNES 的子調色盤）。
6. 地形圖塊要**能無縫拼接**；同一種地面做 2～3 個變體，由外殼依 `(x,y)` 的雜湊挑選，不能看出格子重複。

## 2. 技術規格

| 項目 | 規格 |
|---|---|
| 圖塊（tile）尺寸 | **16×16** 原始像素 |
| 角色尺寸 | **16×24**，腳底對齊所在格的底邊，頭部往上疊到上一格 |
| 道具（地上素材） | 16×16 |
| 氣泡（！／？） | 8×10 |
| 視窗 | 大小跟著螢幕走（見下一列），短邊至少 9 格；鏡頭永遠把玩家放在正中央，地圖以外的範圍是黑的 |
| 放大 | **整數倍**，畫面填滿 HUD 和方向盤之間的空間：倍率＝`floor(min(可用寬, 可用高) / (9×16))`，最小 2 倍（短邊至少看得到 9 格）；顯示範圍＝可用空間 ÷ 倍率，不必是整格（邊緣可以露出半格），最多 17×21 格；不做非整數縮放；`imageSmoothingEnabled = false`，CSS 設 `image-rendering: pixelated` |
| 繪製 | `<canvas>` 2D。依序畫：地面 → 記憶中（現在看不到）的擺設與道具 → 迷霧 → 侍衛視野色（畫在地上，不蓋到角色）→ 依 y 排序、現在看得到的擺設、道具、角色與陰影 → 氣泡與特效 |

### 2.1 素材的檔案格式（程式內嵌的調色盤字串）

所有像素圖都**手工寫成調色盤索引字串**，放在 `js/pixelart.js`。這個檔是純資料：不碰 DOM，Node 也可以載入。載入時由外殼畫成離屏的 canvas 圖集並快取。採用這個格式的理由：可以 diff、可以版控、不用生圖工具，邊緣永遠銳利。

```js
// js/pixelart.js（示意）
const PIXEL = {
  palette: { '.': null, k: '#1b1424', s: '#f6d6bd', l: '#a9cdec', /* … */ },
  sprites: {
    ling_down_0: { w: 16, h: 24, rows: [
      '......kkkk......',
      /* …共 24 列，每列 16 字… */
    ]},
    ling_right_0: { mirror: 'ling_left_0' }, // 允許水平鏡像
  },
  anims: { water: ['pond_0', 'pond_1'], rare: ['catnip_0', 'catnip_1'] },
};
```

- `.` 是透明，其他每個字元都必須在 `palette` 裡。
- 單元測試會檢查：每列長度等於 `w`、列數等於 `h`、字元都在調色盤裡、§3 清單裡的 id 一個不缺、每張 sprite 不超過 16 色。
- 另外做 `tools/pixel-preview.html`：把所有 sprite 以 4 倍、標上 id 排成一頁，再拼御花園與太醫院各一個 11×13 的示範房間（含動畫），方便人工驗收。打開檔案就能看，不需要伺服器。

### 3.5 HUD 與 UI（DOM＋CSS，不畫在 canvas 上）

- **SNES 式視窗框**：深藍漸層底（`#1c2a6b → #0d143d`），2px 白框，外圍再加 1px 深色邊，邊角做 2px 階梯圓角。HUD、結算提示、按鈕都用這個框。
- **頂部 HUD**：剩餘步數（`剩 42 / 60`，配一顆會逐漸變暗的太陽小圖示）、這趟已撿的素材小圖示加數量、「收工」按鈕。
- **手機 3×3 方向盤**：放在畫面底部，中央格留空（沒有「原地等」）。每格 44×36px，八方向用像素箭頭。
- **被抓對話框**：SNES 視窗，貼在遊戲畫面底部，第一行是說話的人（金色小字），第二行是台詞（御花園：侍衛「小主，請回宮。」）。
- **電腦按鍵提示**：小字 `QWE / A D / ZXC 或方向鍵移動・Esc 收工`。
- 字型沿用現有字型，不外連網路字型，用視窗框營造像素感。

| 狀態 | 呈現 |

## 5. 動畫與節奏

- 每走一步用 **120ms** 補間滑過一格，同時播 3 幀走路動畫。侍衛跟玩家同步補間。
- 補間進行中按下的鍵會被記下來（最多 1 個），補間結束才執行。按住不放時每 150ms 重複一步。
- 待機動畫 2Hz：水面波光、稀有閃光、角色呼吸（站姿上下 1px）。
- 侍衛發現玩家：冒「！」氣泡 0.6 秒，加短促的警示音。被抓：畫面白閃一次，侍衛跳一下，再出結算。

### 5.1 進出模式的轉場（「進入不同模式」的清晰感）

1. **進場**：主畫面用 8 條直式百葉往下收成黑（300ms），接著 canvas 從 8×8 馬賽克漸清到 1×1（400ms，SNES mosaic 的效果），同時播進場小旋律。主 BGM 暫停，改放場景內的 8-bit 潛行循環曲（方波＋三角波，五聲音階，WebAudio 合成，沿用 `audio.js` 的合成架構）。
2. **出場**：反過來，馬賽克變粗 → 黑 → 回到主畫面的結算 sheet，主 BGM 恢復。

### 5.2 音效（WebAudio 合成，加進 `audio.js` 的 `SFX`）

`step`（很輕的腳步聲）、`bump`（撞牆）、`pick`、`pickRare`（上行琶音）、`alert`（「！」）、`lost`（「？」）、`caught`（下行）、`timeout`（鑼）、`enterDungeon` / `exitDungeon`。
