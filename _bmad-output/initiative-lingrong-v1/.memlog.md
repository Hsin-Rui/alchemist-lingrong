- (direction) 既有可玩原型《煉金術士零溶》要打磨成可分享的 v1；視為既有程式庫，不重寫，分三方向推進：打磨、內容、美術體驗
- (note) game-design.md v0.4 原樣採用為 adopted companion，不改寫；需求只在 initiative 寫精簡能力線，細節看設計文件
- (requirement) R1(design-doc): 依 v0.4 設計的 10 天一輪能從頭玩到結局，無卡死/錯誤，數值與節奏手感經調校
- (requirement) R2(design-doc): 遊戲內容完整對齊 v0.4 設計（訂單/素材配方/加料/翻牌子/枕邊風/聖旨封號結局），設計到但尚未實作的補齊
- (requirement) R3(design-doc §12): 使用者選入本輪的新內容/玩法（點子庫）在不破壞既有流程下加入
- (requirement) R4(design-doc §10): UI、畫面轉場、立繪/背景整合與音樂呈現一致的宮廷質感，手機直式優先
- (requirement) R5(design-doc §11): 以靜態網站（如 GitHub Pages）部署，朋友可用連結直接遊玩
- (constraint) 純 HTML/CSS/JS 無後端、不做存檔；手機直式優先；畫面不出現英文（台語用字 a 保留）
- (question) 目前原型已實作到 v0.4 的哪些部分、哪些尚未做？決定『打磨』與『內容』兩 epic 的界線
- (question) §12 點子庫哪些納入本輪 v1、哪些留待之後？
- (event) initiative 初版 derive
- (event) 程式稽核＋node 假DOM headless harness 實測：v0.4 設計已全數實作；20/20 自動玩到結局、0 錯誤 0 卡死；#結局 與模擬器均正常。R2（內容對齊設計）視為已滿足
- (direction) 本輪重心調整為三件實際開發：(A)代碼品質重構 game.js/data.js 單體；(B)開發新玩法；(C)提升 UX。原 polish/修bug 導向取消（遊戲已穩）
- (note) 重構需回歸安全網：已有的 headless harness 應正式納入 repo 當回歸測試
- (requirement) R6(direction): 從 game.js 抽出不依賴 DOM 的純遊戲引擎（狀態/規則/流程/結算/加料/結局判定），行為不變；為引擎寫單元測試；模擬器改用同一引擎以消除規則重複；harness 納入 repo 當回歸測試
- (decision) 架構採 functional core / imperative shell（純引擎＋UI外殼），不採 hexagonal——單人純前端無外部可抽換介面，hexagonal 屬過度設計
- (decision) R3 新玩法首選：把採集做成可互動小遊戲（進地圖、與物件互動）；概念開放，Epic 2 先 shaping 再切 story
- (decision) R4 UX 首要：電腦版鍵盤操作支援；新玩法帶出的新 UI 一併設計
- (decision) 原邊界『不重寫架構、維持單一 game.js』撤銷：改為刻意的、行為不變的引擎抽離重構（仍不加後端/框架）
- (event) 三 epic 定案：1 代碼品質重構(引擎+測試) → 2 採集互動小遊戲 → 3 UX(鍵盤+新UI)
